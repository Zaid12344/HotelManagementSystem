Startup / configuration (runtime entry)

  • Program.cs
    • Reads DefaultConnection and registers ApplicationDbContext (SQL Server).
    • Configures Identity with ApplicationUser, roles, and EF stores.
    • Configures cookie paths and auth options (/Account/Login, etc.).
    • Adds MVC controllers + views and registers scoped application services:
      • ReservationService, CheckInOutService, BillingService, InvoicePdfService (registered but implementation not found during review).
    • Builds pipeline: HTTPS, static files, routing, UseAuthentication(), UseAuthorization().
    • Maps controller routes and Razor Pages.
    • Calls DbSeeder.SeedAsync(scope.ServiceProvider) to seed roles/admin on startup (the seeder invocation is present in Program.cs; I could not locate the seeder implementation file in the reviewed files).

Data model (EF Core)

  • ApplicationDbContext defines DbSets for all domain entities and configures indexes, precision for money fields, and relationships:
    • Room — unique RoomNumber, Rate with decimal precision, Status (Available/Occupied/Maintenance/Cleaning).
    • Reservation — booking reference (unique), guest FK, check-in/out dates, deposit/total amounts, Status.
    • ReservationRoom — links reservation to rooms, contains NightlyRate snapshot; unique index prevents same room twice in same reservation.
    • Folio and FolioLine — folio represents the guest account during stay, FolioLine items for charges/taxes/adjustments; folio has TotalCharges, TotalPaid.
    • Payment — receipts with ReceiptNumber (unique), Method, Amount, refund tracking.

Core services and business logic

  • ReservationService
    • GetAvailableRoomsAsync(checkIn, checkOut, excludeReservationId?)
      • Finds rooms not in maintenance and not already booked in the given date range.
      • Overlap rule: existing.CheckIn < new.CheckOut AND existing.CheckOut > new.CheckIn (standard interval overlap).
    • GenerateBookingReferenceAsync() builds BK-YYYYMMDD-####.
  • CheckInOutService
    • CheckInAsync(reservationId, notes?)
      • Loads reservation + linked rooms.
      • Validates reservation status.
      • Generates folio number FOL-YYYYMMDD-####.
      • Creates a new Folio, posts room charges (uses ReservationRoom.NightlyRate snapshot * nights), marks rooms as Occupied.
      • Adds tax line if configured via HotelSettings.TaxRatePercent.
      • Applies deposit as an adjustment line and sets folio.TotalPaid.
      • Computes folio.TotalCharges and saves everything.
    • CheckOutAsync(reservationId, allowUnpaid=false, overrideReason=null)
      • Ensures reservation is CheckedIn, finds open folio.
      • Computes balance (charges minus TotalPaid).
      • If balance > 0 and allowUnpaid==false throws; if allowUnpaid requires overrideReason.
      • Sets folio Status = Settled, closes folio, marks reservation CheckedOut, and sets rooms Cleaning.
  • BillingService
    • GenerateReceiptNumberAsync() → RCP-YYYYMMDD-####.
    • RecordPaymentAsync(folioId, amount, method, ...)
      • Validates folio exists and not already settled, amount > 0 and not exceeding balance.
      • Adds Payment, increases folio.TotalPaid, saves. (Payment collection / integration with payment gateways is not implemented here.)
    • IsFolioFullyPaidAsync(folioId) checks zero-balance tolerance.

Typical user workflows (how the pieces connect)

  1. Booking / Reservation
    • UI/controller constructs a Reservation with Guest, dates, number of guests, deposit.
    • ReservationService.GenerateBookingReferenceAsync() used to assign a unique booking reference.
    • When selecting rooms, system calls ReservationService.GetAvailableRoomsAsync() to present only free rooms (applies maintenance/overlap rules).
  2. Check-in
    • Operator triggers check-in (calls CheckInOutService.CheckInAsync(reservationId)).
    • Service creates a Folio, posts room-charge FolioLines and tax, applies deposit as negative adjustment and sets Folio.TotalPaid.
    • Rooms linked to the reservation are set to Occupied.
  3. Payments
    • Payments are recorded via BillingService.RecordPaymentAsync(...).
    • Each payment gets a receipt number and increments Folio.TotalPaid.
    • BillingService.IsFolioFullyPaidAsync can be used to determine readiness for checkout.
  4. Check-out
    • Operator triggers checkout (CheckInOutService.CheckOutAsync).
    • Service verifies balance (or allows override with reason), marks folio as Settled, reservation CheckedOut.
    • Rooms are set to Cleaning.
  5. Reports / Invoices
    • InvoicePdfService is registered in DI (expected to generate PDF invoices using QuestPDF), but I didn’t find its implementation file. QuestPDF package is included in the project.
